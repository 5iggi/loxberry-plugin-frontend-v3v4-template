# CSS Guide

## Goal

The CSS should work on LoxBerry v3 and v4 without unnecessarily overriding global LoxBerry or jQuery Mobile styles.

## Scope

All custom styles should be scoped below a unique wrapper:

```css
.plugin-page { ... }
.plugin-page .plugin-card { ... }
.plugin-page .plugin-button { ... }
```

Avoid global rules like:

```css
button { ... }
input { ... }
.ui-btn { ... }
```

Global rules may affect LoxBerry core pages, jQuery Mobile or other plugins.

## v4 variables with v3 fallbacks

For a v4-like look, CSS variables can be used. Always provide fallbacks for v3:

```css
.plugin-page {
  --plugin-primary: var(--lb-btn-primary-bg, var(--lb-primary, #6dac20));
  --plugin-danger: var(--lb-danger, #d9534f);
  --plugin-border: var(--lb-border-color, #d8dce0);
}
```

## Buttons

Custom buttons should use both LoxBerry classes and plugin classes:

```html
<button class="lb-btn lb-btn-primary plugin-button plugin-button-primary" data-role="none">
  <i class="pi pi-check"></i>
  <span>Save</span>
</button>
```

Recommended meaning:

- Standard button: neutral
- Save/primary action: `plugin-button-primary`
- Stop/delete/critical action: `plugin-button-danger`

## jQuery Mobile guard

Use `data-role="none"` on custom controls when jQuery Mobile should not enhance the markup:

```html
<input class="lb-input" data-role="none" type="text">
<a class="lb-btn plugin-button" data-role="none" href="#">Action</a>
```

## LoxBerry-generated log list

The log list is generated by LoxBerry. The template does not replace it. It only styles it inside the plugin scope:

```css
.plugin-page .plugin-loglist .ui-collapsible-heading-toggle { ... }
.plugin-page .plugin-loglist a[href*="logfile.cgi"] { ... }
```

This keeps logviewer URLs, LoxBerry JavaScript and loglevel controls intact.

## PrimeIcons

PrimeIcons can be added directly to custom buttons:

```html
<i class="pi pi-refresh"></i>
```

For LoxBerry-generated logviewer buttons, a small JavaScript helper can add an icon without changing the generated system URL.
